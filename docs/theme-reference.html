01 — Orientation

Who owns what

WordPress decides which file renders a request. WooCommerce decides what goes inside its own pages, and substitutes its templates into the WordPress decision. Almost every confusion in shop theming comes from mixing these two up.

WordPress owns

  • The query → template decision (the template hierarchy)
  • Every core template file: index.php, single.php, page.php, archive.php, search.php, 404.php…
  • Template partials: header.php, footer.php, sidebar.php, comments.php
  • functions.php, style.css and the theme header
  • Child-theme overriding of parent files

WooCommerce owns

  • Substituting its own templates into the WordPress decision
  • The markup inside shop pages, via its template files and hooks
  • The product post type and its taxonomies
  • Cart / checkout / account content — but not their templates, which are ordinary WordPress pages
  • Registered image sizes and the product gallery
The minimum theme. The handbook states that with the exception of index.php, you choose whether to implement any particular template file — if no template matches, index.php is used. Separately, for acceptance into the WordPress.org directory it lists style.css, index.php, comments.php and a screenshot as required. Doc
Classic vs block themes. The handbook says the hierarchy is the same for both — block themes simply use .html files instead of .php, and put template parts in a parts/ folder. This atlas covers the classic (PHP) path in depth, because that is what DaimZap is. Doc

    06 — WooCommerce

    Integrating WooCommerce

    Everything in this section is documented in the WooCommerce docs you supplied. Doc

    Three ways to integrate

    • woocommerce.php — duplicate page.php, replace the loop with woocommerce_content(). A catch-all for every WooCommerce taxonomy and post type. The docs note it takes priority over archive-product.php, which then cannot be overridden.
    • Hooks — unhook woocommerce_output_content_wrapper from woocommerce_before_main_content / woocommerce_after_main_content and hook your own wrappers. The docs call this more robust and recommend it.
    • Template overrides — the most control, the most maintenance: templates must be kept up to date with core.

    Overriding a template

    • Copy the file into a /woocommerce/ folder in your theme, keeping the same structure but removing the /templates/ segment.
    • Documented example: woocommerce/templates/emails/admin-new-order.php → yourtheme/woocommerce/emails/admin-new-order.php.
    • Never delete a hook from an overridden template — plugins hook into them.
    • Never edit the files inside the plugin; updates overwrite them.
    • Overrides only work if the theme declares WooCommerce support.
    Declaring support is not optional. The docs state that template overrides are only enabled for themes that declare support; without it, WooCommerce "will assume the theme is not designed for WooCommerce compatibility and will use shortcode-based unsupported theme rendering to display the shop." Use add_theme_support( 'woocommerce' ) on after_setup_theme, not init. Doc

    Conditional tags

    FunctionTrue when
    is_woocommerce()On a page using WooCommerce templates. Cart and checkout are excluded — they are standard pages with shortcodes.
    is_shop()The product archive (shop) page
    is_product_category()A product category archive; accepts a slug or array of slugs
    is_product_tag()A product tag archive
    is_product()A single product page (wrapper for is_singular)
    is_cart() / is_checkout()The cart / checkout page
    is_account_page()Any customer account page
    is_wc_endpoint_url()A WooCommerce endpoint; optionally a named one, e.g. 'order-pay'
    Timing trap. Conditional tags only work after the posts_selection action — the wp hook is the first place they are usable. Called too early they silently return false rather than erroring. Doc
    Dropping WooCommerce's stylesheet. add_filter( 'woocommerce_enqueue_styles', '__return_false' ); removes it entirely, giving you a blank canvas. The docs warn that styling WooCommerce from scratch is "no easy task". Doc
